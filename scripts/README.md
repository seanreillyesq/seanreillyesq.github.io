# Site lint

`lint-site.py` is the pull request quality gate, run by the `lint` job in `.github/workflows/deploy.yml` before anything is deployed. From the source it checks that posts have valid front matter (`title`, `date`, `layout: post`, `categories`), that filenames follow `YYYY-MM-DD-kebab-case-slug.md`, that every `hidden: true` post also has `robots: noindex`, that `header-img` files exist, that no post or page body contains an em or en dash, and that post bodies avoid the house-style banned words and phrases. From the built `_site/` it checks that every site-relative `<a href>` and `<img src>` resolves to a file or a directory with an `index.html` (external URLs, `mailto:`, `tel:`, anchors and `/files/` are ignored) and that every `<img>` has a non-empty `alt`. Findings print as `LEVEL path: message`; any FAIL gives exit status 1.

To run it locally, build the site and lint it: `JEKYLL_ENV=production bundle exec jekyll build && python3 scripts/lint-site.py --source . --site _site`. It needs Python 3 and nothing else. Checks listed in `WARN_CHECKS` at the top of the script print as WARN and do not fail the run, which lets known existing content through while it is cleaned up. Add `--strict` to treat every WARN as FAIL, and remove a check from `WARN_CHECKS` to promote it permanently.
